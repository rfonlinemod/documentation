Animus (Summon Companion System)

Server Client Ships off Hot-reload

What it does — and why you would use it

An animus is a summonable companion creature that fights beside its owner — the four species Paimon, Hecate, Inanna and Isis, each also sold in a stronger sealed / _S form. They gain experience as you play, level up, and can be recalled to follow you, attack, target or heal. Everything about them — how much FP a summon costs, how fast they level, how far they wander, what stats each level has, and how they are shown on screen — is normally hard-coded inside the server and client binaries.

The Animus feature lifts all of that into a folder of plain-text .lua config files. Each file controls one area of the system and has its own Enable switch. While a file’s Enable = false the game behaves exactly as stock (every shipped default in these files is the current game value, so switching a file on without editing anything changes nothing). Flip a file to Enable = true and the numbers you write take over — no recompiling, and the running Zone server notices a saved edit in about half a second.

Server-side and client-side filesEight of the ten files tune the Server (gameplay maths and the stat table). Three of them also reach the Client (the Summoning board display, packet handling and command hotkeys) — the game client runs no Lua of its own, so the server reads those files and pushes the resolved values to every player’s client automatically. Client-side effects only appear for a game client that was rebuilt with Animus support; an unmodified client simply ignores the push and keeps its stock behaviour.

The 10 config files

All ten live together in .Server\Zoneserver\RF_Bin\Modules\Animus\. They are independent — you can turn on any subset. Each is a single Lua table with an Enable line at the top and the knobs below it.

FileSideWhat it governs
DModStorage.luaServerDocuments the data model (where exp / HP / FP / level are stored) and the operator-facing capacity numbers. Mostly informational — the compiled field layout cannot be relocated from a config file.
DtableScript.luaServer ClientThe full animus stat table — every level of every species (HP, FP, attack, defence, resistances, recovery…). When on it overrides both the server’s in-memory stat structs and the client’s Character.edf rows. This is the flagship file, detailed below.
NetProtocol.luaServerThe animus wire-protocol family id and per-message enable. Almost entirely informational — renumbering the wire requires a matching rebuilt client, so the id is force-kept at the stock value.
SRecallReturnCycle.luaServerSummon / recall rules: FP cost, re-summon cooldown, the mastery gate, FP-drain interval, idle / max-distance / death auto-return timings.
SCombatAI.luaServerCombat behaviour: the mode a fresh summon starts in, a forced target-acquisition radius, and whether attack / target / move commands are honoured.
SLvlExp.luaServerExperience maths: the level-difference gate, the kill / hit exp divisors, heal and defence exp multipliers, a hard level cap, and a one-off reset of already-over-levelled animus.

CPacketPros.luaClientHow the client resolves which animus a packet refers to — by the server storage serial (robust) or the legacy client datatable index.
CHotkey.luaClientThe three animus command keys (attack / target / move) as Windows virtual-key codes, overriding the client’s KeyMap.dat bindings.

How to activate it

  1. Open the folder. Go to .Server\Zoneserver\RF_Bin\Modules\Animus\ and open the file you want to tune in Notepad. Each file opens with a plain-English guide at the top.
  2. Flip that file’s switch. Find the Enable = false line near the top of the table and change false to true (lowercase): 
    AnimusRecallReturn =
{
    Enable                = true,   -- was false
    RecallFPCost          = 60,
    ...
}
    Saving applies it live — a running Zone server picks it up in about half a second, no restart.
  3. Change only the numbers you care about. Every knob already sits at its stock value, so you edit just the ones you want to move. Omit / leave a line and it keeps that stock value.
  4. Client knobs need a rebuilt client. CBoardUi, CPacketPros and CHotkey only do something when players run a client that has the Animus push compiled in; a stock client ignores them.
  5. Revert any time. Set a file back to Enable = false and save — that area returns byte-for-byte to stock instantly.
Do not delete these files, and one deploy noteLike every module, the Animus files are required when the Zone server starts — a missing file stops it booting. To turn the feature off, set Enable = false, never remove the file. Also, because this feature overrides the compiled stat table and pushes it to the client, it only fully works when you are running the current Zone server executable and a matching rebuilt RF_Online.bin client. With an older binary the config is read but the deep overrides / client push will not take effect.

Server behaviour knobs

These are the everyday gameplay tunables. Every value below is the shipped default (so Enable = true with no edits = stock). Ranges are enforced by the server: a typo or out-of-range number is clamped to the safe bound rather than corrupting anything.

The stat-table override (DtableScript.lua)

This is the big one. It is the complete animus stat table — one row for every (Type, Level) pair. While Enable = true it patches the server’s in-memory stat structs and ships every row to each client to patch its Character.edf animus rows, so both sides stay in sync (which matters because the client derives the level, exp-bar and HP/FP denominators from its own copy).

It ships with Enable = false and a full, correct set of 800 rows (all 16 types × levels 1–50) extracted from the real game data. With no edits and Enable = true, gameplay is unchanged — you then tune individual rows, save, and the zone hot-reloads and re-pushes the changed grid to every in-world client.

The row format

Grid =
{
    { Type="Pai", Level=1, NeedExp=200, MaxHP=31, MaxFP=50, HPRecPoint=5, HPRecDelay=2000,
      FPRecPoint=4, FPRecDelay=2000, AttackPower=0, DefencePower=15, ForcePower=16,
      AttSklUnit=4, DefSklUnit=1, WeakPart=-1, Fire=0, Water=0, Soil=0, Wind=0,
      AttackDelay=1, AttackRange=45, MoveSpeed=6, Width=20, Scale=100,
      AttEffType=1, DefEffType=512 },
    ...
}
  • Type — the animus species. Write it either as the numeric index 0..15 or as a quoted name (case-insensitive): e.g. Type=0 and Type="Pai" mean the same row. It must be quoted — a bare Type=Pai is not valid Lua and that row is skipped.
  • Level — 1..50. The client block stride is 50, so levels 51–81 exist only in the server’s .dat and are not shown here.
  • NeedExp — the exp threshold for that level; must be strictly increasing within a species.

Any (Type, Level) row you omit keeps its stock value — but do not delete a column from a row, because an omitted column defaults to 0 and would corrupt a field that is read.

Rules & limits

  • Off = stock. Every shipped default reproduces the current game; with all ten files at Enable = false the deployed state is behaviourally identical to an untouched server. Turn on only the areas you intend to change.
  • Ownership is four. A player can register four animus at once (a compiled DB / protocol limit — raising it needs a database + protocol migration, not a config edit). The Summoning window shows a ten-row type catalog (one socket per type, including sealed types); that catalog is separate from the four owned slots and RegisteredCapacity in DModStorage.lua is only informational here.
  • Levels 1–50 on the client. The stat grid covers levels 1–50 because that is the client block size; the server .dat still holds 51–81, which stay as shipped unless you also add them.
  • Some files are informational. DModStorage.lua (data model) and NetProtocol.lua (wire family id, force-kept at 22) describe compiled behaviour that a config file cannot rewire — changing their numbers without a matching rebuilt client / DB migration will not move the wire or field layout.
  • Keep exp thresholds monotonic. In DtableScript.lua, a species’ NeedExp must strictly increase with level, or the exp-to-level curve misbehaves.
  • Current binaries required. The deep stat-table override and the client push only work on the current Zone server exe plus a matching rebuilt RF_Online.bin. On an older binary the config is read but those effects will not appear.
