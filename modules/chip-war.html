Chip War Control Panel

Server-only Ships off Hot-reload

What it does — and why you would use it

The chip war (also called the crystal or Holy Stone war) is the server's repeating three-team battle. The teams are Bellato, Cora and Accretia; each guards its own crystal, and they fight to smash the rivals' crystals. When the fighting window closes, the team still holding its crystal wins the right to defend the keeper (a guard creature) and mine ore in peace.

Normally re-tuning that event means editing NewHolySystem.ini by hand and, for a couple of behaviours, recompiling the server. The Chip War Control Panel is a single plain-language ChipWar.lua file that lets you drive almost the whole event instead — no programming, no recompiling:

  • Phase timings — how long each stage of the war lasts (the main battle, the keeper windows, the mining phase and so on).
  • Crystal and keeper strength — how tough each crystal is (including whether it scales with how many players are online) and what percentage health the keeper starts at.
  • Basic switches — how many crystals are in play, free mining, and the mental-pass rule.
  • Scanner points and ore — the Holy-Scanner score deltas awarded on a win / loss, and the winning team's ore-mining amounts and per-day bonus multipliers.
  • The loot lists — exactly which items drop when a crystal or the keeper is destroyed, split per team for the crystals.

How to activate it

  1. Open the control panel. Edit .Server\Zoneserver\RF_Bin\Modules\ChipWar\ChipWar.lua in Notepad. The file opens with a plain-English guide at the top.
  2. Flip the one switch. Find the line near the top and change false to true (lowercase): 
    ChipWar = {
  Enable = true,
  ...
    Saving applies it live — a running Zone server notices the change in about a second, no restart.
  3. Adjust only what you care about. Each block is separated by a banner comment. The popular ones are the loot lists, the crystal / keeper toughness and the phase timings. Change the number after the = and save.
  4. Nothing to do on the client. Players' game clients need no file and no setting — they just see the war follow your new rules.
  5. Revert any time. Put Enable = false back and save; the war instantly returns to the stock NewHolySystem.ini behaviour.
One timing caveat, and don't delete the fileEvery setting here hot-reloads immediately except the phase timings: a war already in progress keeps the clock it started with, so SceneTerms edits take effect at the start of the next war. Also, like every module file, ChipWar.lua is required when the Zone server starts — deleting it stops the server from booting. To switch the feature off, set Enable = false instead of removing the file.

The control panel

Everything lives in one ChipWar = { ... } block. You only ever change the value after the =. Times are in milliseconds (1000 = 1 second, 60000 = 1 minute, 3600000 = 1 hour). Here is what each group controls and the stock default it reproduces.

The loot lists

When Enable = true, the lists in this file completely replace the game's normal loot tables for the crystal and the keeper — what you write is exactly what drops. Leave a list empty and that thing drops nothing.

  • The crystals are per team. There are three crystals, one owned by each race, so ChipDrops holds three separate lists: Bellato, Cora and Accretia. When a crystal dies, the loot that falls is the list of the team that owned it, so you can make each team drop different things. The three lists start out identical.
  • The keeper is one creature, so it has a single KeeperDrops list.

Add an item by copying one line inside the right list:

{ Item = "irtal01", Count = 1, Chance = 10000 },
  • Item — the item's code, in quotes (find it in your item list).
  • Count — how many (for a stackable item this is one box holding Count).
  • Chance — 0 to 10000: 10000 drops every time, 5000 about half, 1000 one in ten, 100 rare.

To switch a single line off without deleting it, put two dashes -- in front of it. To remove it entirely, delete the whole line.

Only when the module is onThe “ignore the normal loot tables” behaviour applies only while Enable = true. With the module off, crystals and the keeper fall their usual built-in ItemLooting loot, exactly as before.

What stays in the .ini

Almost every war setting is now here, but a few groups in NewHolySystem.ini are deliberately not live knobs in this file. The control panel lists them at the bottom as comments so nothing feels missing; you still change them in the ini and restart.

  • Spawn topology. The crystal and keeper create-map, the create / active / centre dummy markers, the monster codes, the per-crystal race ownership, the portal dummy names, the HolyMental item and the RaceBuff scanner codes. The server creates the three crystals and the keeper from these values at start-up — before this Lua is ever read — so re-pointing them mid-run would move the sign-post but leave the creature where it was spawned. Edit them in NewHolySystem.ini and restart.
  • Dead switches (marked UNUSED). The old [RaceBattleRewardItem] Fix / Rate item lists and the misspelled WinGetScanet point key are read by no current code. The real loot now comes from the drop lists above, and the five scanner deltas that are honoured live under RaceBattlePoint. They are documented in the file only for honesty.

With the module off, the war behaves identically to stock: every timing, HP, point and ore value comes from NewHolySystem.ini, and crystals and the keeper drop their normal ItemLooting loot.
