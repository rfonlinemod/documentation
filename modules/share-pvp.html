Share PvP

Server Ships off Hot-reload

What it does — and why you would use it

When a player kills another player the game hands out two rewards: CPT (the PvP rating point) and PvP temporary cash. In the stock game the split is hard-coded — the killer keeps 70% of the CPT and all of the temporary cash, and only the leftover 30% of CPT trickles to the killer’s nearby party. Share PvP lets you choose that split yourself, separately for each reward pool, and to scale the cash reward up or down.

Use it to:

  • Reward whole PvP gangs, not just the last hitter — share the CPT and/or the cash evenly across the party.
  • Tune your PvP economy with per-role cash multipliers (killer with a party, solo killer, and the victim’s loss).
  • Hand out a flat, predictable amount of temp cash per kill / per death instead of the engine’s computed figure.

“Nearby party members” means the killer’s live, same-map party members inside the normal party circle, not counting the killer. There is no separate radius to set.

Server-only, and inert until you change a valueThis module changes only what the server does — nothing is pushed to the player’s client and there is no client file. With Enable = 0 (the shipped default) the game behaves exactly as stock, and even after you set Enable = 1 the shipped values (Type 0, ×1.0 multipliers, 0 fixed amounts) reproduce stock behaviour until you edit one.

How to activate it (the INI)

  1. Turn the feature on. Open .Server\Zoneserver\RF_Bin\Modules\PlayerManager\SharePvP.ini in Notepad and change the Enable line under [General]: 
    [General]
Enable = 1
    Save the file — a running Zone server picks it up within a second; no restart needed.
  2. Pick your split types and multipliers. Edit the [CPT] and [PvPTempCash] keys described in The config file.
  3. Test it. Have two party members kill an enemy player and watch how the CPT and temp cash land. Tweak the file, save, and the new rules apply to the very next kill.
Do not delete the fileLike every module, SharePvP.ini is required when the Zone server starts — deleting it stops the server from booting. To turn the feature off, set Enable = 0 instead. (The optional SharePvP.lua is the one exception — it is never required and may be absent.)

The config file

Every key lives in Modules\PlayerManager\SharePvP.ini. Change a value, save, and the next PvP kill uses it — the file is hot-reloaded about twice a second.

Section & keyValuesWhat it does
[General] Enable0 / 1Master switch. 0 = stock reward handling (module off).
[CPT] Type0 / 1 / 2How the CPT point is split. 0 = killer 70% / party 30% (level-weighted, stock); 1 = killer 50% / party 50% (level-weighted); 2 = equal share among killer + every nearby member (a total of 100 among 4 = 25 each).
[PvPTempCash] Type0–3How the temp cash is split. 0 = killer takes all (stock); 1 = 70/30; 2 = 50/50; 3 = equal among killer + party.
[PvPTempCash] KillerCashMultiplyfloat, e.g. 1.5Extra multiplier on the temp-cash reward for a killer who has nearby party. Neutral = 1.0.
[PvPTempCash] SoloKillerCashMultiplyfloatMultiplier for a killer with no nearby party. Neutral = 1.0.
[PvPTempCash] DierCashMultiplyfloatMultiplier on the victim’s temp-cash loss. Neutral = 1.0.
[General] FixedPvPTempCashPerKillint, 0 = offReplace the killer’s computed cash gain with this flat amount (the killer multipliers then apply on top). 0 keeps the engine’s value.
[General] FixedPvPTempCashPerDeathint, 0 = offReplace the victim’s computed cash loss with this flat amount (then DierCashMultiply applies). 0 keeps the engine’s value.

Two keys — ShareRadius and ShareCashQuest — are read only to match the original Odin file and currently have no effect: the party-circle radius is fixed in the engine and shared with non-PvP code, and the temp-cash path exposes no quest trigger. Leave them at their shipped values.

Optional: drive it from SharePvP.lua

If you would rather keep your PvP-sharing rules in one clean Lua list, drop a SharePvP.lua beside the INI. The server notices it automatically — the moment the file appears it starts watching and hot-reloading it, so you never touch the INI and never restart.

Nothing to “enable” in the INIJust create .Server\Zoneserver\RF_Bin\Modules\PlayerManager\SharePvP.lua with Enable = true inside it. While that file is present and switched on, the server follows the Lua and ignores the sharing keys in SharePvP.ini. Set Enable = false or delete the file and the INI takes over again.
SharePvP = {
  Enable = true,          -- true = the server follows THIS file, not the INI

  CptType  = 2,           -- 0 = 70/30, 1 = 50/50, 2 = equal party split
  CashType = 1,           -- 0 = killer all, 1 = 70/30, 2 = 50/50, 3 = equal

  KillerCashMultiply     = 1.5,   -- killer WITH nearby party
  SoloKillerCashMultiply = 1.0,   -- killer with NO nearby party
  DierCashMultiply       = 1.0,   -- the victim's loss

  FixedPvPTempCashPerKill  = 0,   -- flat cash per kill, 0 = use the engine value
  FixedPvPTempCashPerDeath = 0,   -- flat cash per death, 0 = use the engine value
}
Lua fieldMatches INI keyNotes
Enable[General] EnableThe switch. true (or 1) = follow this file; false (or 0) = ignore it and use the INI.
CptType[CPT] Type0–2; a value out of range falls back to 0.
CashType[PvPTempCash] Type0–3; out of range falls back to 0.
KillerCashMultiply / SoloKillerCashMultiply / DierCashMultiplysame names in [PvPTempCash]Floats, default 1.0.
FixedPvPTempCashPerKill / FixedPvPTempCashPerDeathsame names in [General]Integers, default 0.
  • Every field is optional. Anything you leave out keeps the neutral default shown above.
  • Comments use --. Everything after two dashes on a line is ignored, so label your rules freely.
  • A typo cannot break your server. If the file has a syntax mistake (or is missing the SharePvP = { ... } table), the server writes a plain-language note into the ModulesLog folder and safely keeps using the INI.
  • It is never required at boot. The Zone server starts fine with no SharePvP.lua at all; only SharePvP.ini must exist. Add the Lua whenever you like and it is picked up live.
