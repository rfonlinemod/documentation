Item Stack Limit (1M Stacks)

Server Client Hot-reload

What it does — and why you would use it

Stock RF Online caps a stackable item (potions, ore, resources, boxes…) at 99 per slot. This feature raises that ceiling to 1,000,000 so a single slot can hold a huge stack. ItemStack.ini / ItemStack.lua are then a restriction gate: you do not list an item to make it stack big — that is already the default — you list it only to give a specific item a smaller cap (or 0 to force it non-stackable).

The big default is baked into both binaries, so it just works; the config is purely for pulling individual items back down. The server resolves each item’s real cap, enforces it everywhere a stack can grow (merge, split, loot, buy / sell / trade, warehouse, and on login) and pushes the exceptions to each client — there is no client file.

PartWhere it livesIts job
Restriction table.Server\Zoneserver\RF_Bin\Modules\ItemStack\ItemStack.ini (+ ItemStack.lua)Lists per-item caps below the 1M default. A Lua code wins over an .ini row.
Client halfNo client file. The server pushes each item’s non-default cap so the client clamps split / combine / use identically. Both the Zone server and the client must be the current build.
The default IS 1,000,000You do not have to list the 12 stackable item tables to make them big — every stackable item already stacks to 1M by default. Editing this file is only how you restrict an item. A row left at 1000000 (or absent) keeps the full ceiling.

How to use / restrict it

  1. Do nothing for the common case. With the current build, stackables already go to 1,000,000. The files ship Enable = 1 but every value at the default, so the shipped behaviour is simply “every stackable stacks to 1M unless you say otherwise.”
  2. To cap one item lower, edit its row in ItemStack.ini under [ItemStack] — the form is tableCode.itemIndex = MAXSTACK: 
    13.0  = 5000    ; cap this potion (table 13) at 5,000
18.40 = 1000    ; cap this resource (table 18) at 1,000
20.5  = 0       ; make this booty (table 20) non-stackable
    Save — it hot-reloads and re-pushes the changed caps to clients.
  3. … or by item code in the Lua. In ItemStack.lua add the code under MaxStack: 
    MaxStack = {
  [ "iopy01" ] = 5000,
}
    A MaxStack code wins over the .ini row for that item.
  4. Test it. Pick up past 99 of a stackable (it merges into one slot up to 1M); split exactly 1,000,000 into an empty slot; for a restricted item, confirm it stops at the number you set while everything else keeps 1M.
Do not delete the fileItemStack.ini is required when the Zone server starts — deleting it stops the server from booting. To stop using the restriction rows but keep 1M stacks, set [Settings] Enable = 0 (the .ini is then ignored and only the Lua, if enabled, restricts).

The config files

Two files in Modules\ItemStack\, each with its own Enable so you can drive the restriction from one, both or neither. Each is auto-generated to list every item explicitly at its stock category default, so the whole behaviour is visible and individually editable.

Key / fieldFileMeaning
Enable.ini [Settings]1 = apply the [ItemStack] rows, 0 = ignore the whole .ini (default 1).
tableCode.itemIndex = N.ini [ItemStack]The cap for one item: 0 = non-stackable, 2..1000000 = that item’s max (1 is treated as non-stack; values above 1M clamp to 1M).
Enable.lua1 = apply the Lua, 0 = ignore it.
Stack / NoStack.luaCodes that stack at the 1M default / codes forced non-stackable.
MaxStack.luaExplicit per-item caps by exact code — the restriction gate; wins over the .ini and over Stack / NoStack.

Resolution priority for an item: Lua MaxStack → .ini row → Lua Stack / NoStack → stock category rule. Anything not explicitly restricted keeps its category default — the 12 stackable tables go to 1M, everything else is non-stackable.

Rules & limits

  • 1M is the hard ceiling. 1,000,000 is both the default for stackables and the maximum; the packet widths and counters are sized for exactly this, so you cannot go above it by config.
  • Some systems deliberately stay at 99. A few byte-only subsystems were left at the old cap so they are not corrupted — mining / auto-mine, ore cutting, the cash shop, the unmanned trader, guard-tower and talk-crystal combine. Those still max at 99.
  • Login trims oversized stacks. If you lower an item’s cap below what a player is already carrying, their stack is clamped down to the new cap when they log in.
  • Lockstep build. Because the count fields were widened, the Zone server and the client must be the matching build; an old client will not understand the new push.

Both files ship listing every item at its default (1M for stackables, 0 for the rest), so the out-of-box behaviour is simply “every stackable item now stacks to 1,000,000.”
