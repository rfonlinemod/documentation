Store System (Shops, Goods & Spawns)

Server Client Ships off Hot-reload

What it does — and why you would use it

The Store System is the whole shop world: every merchant NPC, what each store sells, its name and price set, which races may trade there, buy / sell limits, the buffer & bind NPCs, how a merchant looks on the client, where a merchant stands — and even which monster fills a spawn point on any map. All of it is normally baked into the shipped StoreList.dat / Store.edf data tables and the compiled server and client binaries.

This feature lifts all of that into a folder of plain-language .lua config files. There are seven files, each controlling one area and each with its own Enable switch. While a file’s Enable = false the game behaves exactly as stock (every shipped default in these files is the current game value, so switching a file on without editing anything changes nothing). Flip a file to Enable = true, edit a row, save — and the running Zone server notices it in about half a second and applies just that change, with no restart and no recompiling.

Server-side and client-side filesMost files tune the Server (the live store records, trade maths, spawn slots). Several also reach the Client (the shop / merchant name, the goods list, the merchant colour, radar marker and buffer badge) — the game client runs no Lua of its own, so the server reads those files and pushes the resolved values to every player’s client automatically over the store message channels. Client-side effects only appear for a game client that was rebuilt with Store-System support; an unmodified client simply ignores the push and keeps its stock Store.edf display.

The 7 config files

All seven live together in .Server\Zoneserver\RF_Bin\Modules\StoreSystem\. They are independent — you can turn on any subset. Each is a single Lua table with an Enable line at the top.

FileSideWhat it governs
DataFoundation.luaServerWhich store codes the feature recognises (EnabledStoreCodes whitelist) and per-store race overrides (RaceOverrides: { Code, Race }). The foundation the other files build on.
OwnershipCreation.luaServerLimited-stock refresh interval, how often store state is saved, the instance-store list size and the daily-limit reset hour.
BroadcastVisibility.luaServer ClientWhether the store list is sent on entry, the store view range, and whether merchants show on the minimap radar.
TradePipeline.luaServerThe buy / sell rules: trade range, cross-race trade gate, buy-price divisor, sell-price permille, global discount, offers-per-transaction cap, NPC-link bypass, and the ticket / trap-boss / gold-box gates.
NpcObjects.luaServer ClientBuffer-store index range, the bind-NPC class and range, the client merchant name colour, the buffer badge, and the buffer aura effect file.
NpcTableScript.luaServer ClientThe authoritative store / goods table — one row per store with its name, trade kind, price set, NPC-class list and the full goods list. When on it replaces the shipped StoreList.dat records and re-pushes the client catalogue. Detailed below.
NpcLocationScript.luaServerLocation / spawn editor in two halves: (A) Grid moves any merchant to a new map / coordinates; (B) MonsterGrid overrides monster spawn points on every map (which monster, respawn timing / count, relocation, disable). Detailed below.

How to activate it

  1. Open the folder. Go to .Server\Zoneserver\RF_Bin\Modules\StoreSystem\ and open the file you want to tune in Notepad. Each file opens with a plain-English guide at the top.
  2. Flip that file’s switch. Find the Enable = false line near the top of the table and change false to true (lowercase): 
    StoreNpcTableScript =
{
    Enable = true,   -- was false
    Grid = { ... },
    ...
}
    Saving applies it live — a running Zone server picks it up in about half a second, no restart.
  3. Change only the rows you care about. Every row already re-states the store’s current value, so Enable = true with no edits is idempotent (nothing moves). Edit just the fields you want to change.
  4. Client effects need a rebuilt client. The shop / goods push, the merchant colour, radar marker and buffer badge only do something when players run a client rebuilt with Store-System support; a stock client ignores them and keeps its own Store.edf rows.
  5. Revert any time. Set a file back to Enable = false and save — that area returns byte-for-byte to stock instantly (and the client gets a reset push).
Do not delete these filesLike every module, the StoreSystem files are required when the Zone server starts — a missing file stops it booting. To turn the feature off, set Enable = false, never remove the file. Also, because this feature overrides the live store records and pushes the catalogue to the client, it only fully works when you run the current Zone server executable plus a matching rebuilt RF_Online.bin client.

Store catalogue & goods (NpcTableScript.lua)

This is the flagship file. It is one row per store in load order. While Enable = true the server patches each store’s live in-memory record and rebuilds its goods from the row (so buying / selling follows this table with no restart), and ships the per-store catalogue to every client so the shop display agrees with the server.

It ships with Enable = false and a full snapshot of the live StoreList table. With no edits and Enable = true, gameplay is unchanged; you then edit a row, save, and the zone hot-reloads and re-applies just that store.

The row format

Grid =
{
    { Index = 3, NpcCode = "03010", Name = "POTION", StoreTrade = 1, PriceSet = 1,
      UpCode = -1, LimitInitTime = 0,
      NpcClass1 = 1, NpcClass2 = 13, NpcClass3 = 2, NpcClass4 = 53, ..., NpcClass10 = 0,
      Goods = { { Code = "ipbhp01", Limit = -1 }, { Code = "ipbhp02", Limit = -1 }, ... } },
    ...
}
FieldMeaning
IndexREQUIRED. The store record’s number in StoreList.dat (0-based). This is the authoritative key that matches the row to a live store.
NpcCodeOPTIONAL safety cross-check (e.g. "03010"). If set, the row only applies when the store matched by Index really has that code — so a wrong Index base silently does nothing instead of overwriting a neighbour shop.
NameThe shop / merchant display name pushed to the client. An empty Name = "" keeps the client’s own name.
StoreTradeThe store trade kind. -1 keeps the record value.
PriceSet / UpCode / LimitInitTimePrice set, item up-code (-1 = keep the shipped value) and the limit-item init time.
NpcClass1..10The ten NPC-class slots. 13 marks a BIND npc.
GoodsThe store’s offered items, each { Code = "..", Limit = n }. Limit ≥ 0 = a per-period limit item capped at n (max 16). Limit < 0 (usually -1) = a plain offered good. An empty Goods = { } means “leave this store’s items untouched”.

Merchant & monster locations (NpcLocationScript.lua)

One file edits two halves of the world, both applied live on the game loop. With Enable = false nothing here changes the game: every merchant stands where its store dummy puts it and every monster respawn is byte-for-byte the shipped map data.

(A) Grid — move a merchant

One row per store NPC you want to relocate. A relocated merchant keeps its OWN shop (goods / race / limits unchanged) — only where it stands moves; buy / sell / bind still work on the new map and its minimap marker follows it.

Grid =
{
    { Index = 0, NpcCode = "03000", MapCode = "NeutralB", X = -4990.0, Y = 575.0, Z = 6546.0, Angle = 9 },
    ...
}
FieldMeaning
IndexREQUIRED. The store record’s number (same key as the catalogue).
NpcCodeOPTIONAL cross-check — the row only applies when the store matched by Index really has this code.
MapCodeOPTIONAL target map code. Empty / omitted = stay on the merchant’s current map (a same-map move).
X, Y, ZDestination coordinates. At least one must be present for the row to do anything; omitted axes default to 0.0.
AngleOPTIONAL facing in degrees. -1 / omitted = leave native.

(B) MonsterGrid — change what spawns

One row per spawn slot, identified by (MapCode, Block, Slot). Every override below is optional (omit = leave the native value).

MonsterGrid =
{
    { MapCode = "NeutralC", MonCode = "00002", NewMonCode = "02A02",
      Block = 0, Slot = 0, RegenTime = 15000, RegenLimNum = 13, RegenProp = 100,
      RegenMinNum = 0, StdKill = 0, RegenMaxNum = 0 },
    ...
}
FieldMeaning
MapCode / Block / SlotREQUIRED identity. The slot’s home map, its _mon_block index (0..199) and the _mon_active index within it (0..299).
MonCodeOPTIONAL identity cross-check: the monster the slot currently holds. If set, the row only applies when that slot really holds this monster.
NewMonCodeThe field that actually changes which monster spawns here (a monster record code). Empty / omitted = keep the current monster.
TargetMapCode / X, Y, Z / DummyCodeRelocate the whole spawn to another map, give an explicit spawn point, or point at a named spawn-area dummy.
RegenTimeRespawn interval in milliseconds.
RegenMaxNum / RegenMinNum / RegenLimNum / RegenProp / StdKillRespawn count / probability (0..100 per pass) and standard-kill controls. Timing / count edits take effect at the next respawn.
Disable1 = kill this slot (its monsters never respawn).
Changing a monster: use NewMonCode, not MonCodeA very common mistake: editing MonCode to the monster you want. MonCode is only a cross-check of what is there now — if you change it to a different code, the check fails (current monster ≠ MonCode) and the whole row is skipped, so the spawn stays as it was. To swap the monster, leave MonCode at its current value (here "00002" young flem) and put the new one in NewMonCode (here "02A02" Anabola). Every monster row now ships with an empty NewMonCode = "" so you just fill it in.

Client look & trade rules

NpcObjects.lua controls how merchants appear on a rebuilt client, and TradePipeline.lua the buy / sell maths. Every value below is the shipped default (so Enable = true with no edits = stock).

Rules & limits

  • Off = stock. Every shipped default reproduces the current game; with all seven files at Enable = false the deployed state is behaviourally identical to an untouched server. Turn on only the areas you intend to change.
  • Match by Index, guard with NpcCode. Store rows are keyed by their Index in StoreList.dat; keep each row’s NpcCode so a wrong Index base results in 0 rows patched (safe) instead of overwriting the wrong shop.
  • Goods limit cap is 16. Per-period limit items (Limit ≥ 0) go into a list holding at most 16; everything else is a plain good. An empty Goods = { } leaves the store’s items untouched.
  • Monster edits use NewMonCode. MonCode is only an identity cross-check — to change a spawn, set NewMonCode and leave MonCode at the current monster. Timing / count edits apply at the next respawn.
  • Malformed rows are skipped, never crash. Any row that cannot be resolved (bad index, unknown code, no coordinates) is logged and skipped; it never blocks map loading.
  • Current binaries required. The live record patch and the client push only work on the current Zone server exe plus a matching rebuilt RF_Online.bin. On an older binary the config is read but those effects will not appear.
