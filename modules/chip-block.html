Chip No-Entry (Chip Block)

Server Client Off by default Hot-reload

What it does — and why you would use it

In a chip war a player can walk straight into a team’s crystal — the “chip” (internally the Holy Stone) — and stand inside its model. From there the other team cannot click or attack them, so whoever camps inside the chip gets a free, unkillable hiding spot. This module closes that hole.

Turn it on and nobody can enter a chip any more. A keep-out circle is drawn around every live chip on every map; a player who walks into it simply slides up to the edge and stops. It is enforced in two layers (see How it blocks): the game client refuses the step so it feels instant, and the Zone server independently rejects any position that would land inside, so a modified or lagging client cannot cheat it.

Like every module here it ships off by default and is driven from one plain-language Lua file that the server hot-reloads — no client file to edit, no restart.

How to activate it

  1. Open the file. .Server\Zoneserver\RF_Bin\Modules\ChipBlock\ChipBlock.lua in Notepad.
  2. Flip the switch. Change Enable = false to Enable = true (lowercase, exactly).
  3. Set the keep-out size. Radius is how far the circle reaches from the chip’s centre in world units. The default 6.0 sits just outside the structure’s walls; nudge it so the wall hugs the chip (a good range is roughly 4 to 12).
  4. Save — no restart. A running zone re-reads the file within about a second and pushes the new radius out to every client.
  5. Test it. Walk a character at a chip — you should stop at the edge. Anyone standing inside when you switch it on is popped back out to the edge the next time they move.
Do not delete the fileChipBlock.lua is required when the Zone server starts — removing it stops the server from booting. To turn the feature off, set Enable = false instead of deleting the file.

The config file

Just two values, with plain-language comments written in the file itself.

ChipBlock = {
  Enable = false,   -- true = players cannot enter any chip; false = off (stock behaviour)
  Radius = 6.0,     -- keep-out circle radius around each chip's centre, in world units
}
KeyDefaultMeaning
EnablefalseMaster switch. true turns the no-entry wall on for every live chip on every map; false leaves movement exactly as stock.
Radius6.0How far the keep-out circle reaches from the chip’s centre, in world units. The server clamps it to a safe 1–200; in practice about 4–12 hugs a chip. Bigger = players are stopped further out.
One number, both sidesYou set Radius only here. The server sends it to every client as part of the normal feature-state push on world entry and after each live reload, so the client’s walk-block and the server’s authority always agree on the same circle — there is no matching client file to edit.

How it blocks (server + client)

The keep-out is applied in two places so it feels smooth and cannot be cheated:

  • Client On each movement step the client checks the player against every chip it already renders. If the next step would land inside a circle, it is pushed back out to the edge — so you visibly slide around the chip instead of clipping through it.
  • Server Independently, the Zone server re-checks every position a client reports (right where it already runs its fly / wall-hack checks) and clamps it out of the circle before accepting it. A hacked or desynced client cannot put itself inside a chip, because the authoritative server simply refuses that position.

It targets all chips, all maps at once, and only crystals that are currently alive are treated as blocked — so a destroyed chip does not leave an invisible wall behind. There is nothing to configure per-chip.
