Auto Loot

Server-only Ships off Hot-reload

What it does — and why you would use it

Auto Loot pulls a mob’s drops straight into the loot owner’s (usually the killer’s) inventory — the “magnet” loot most private servers run — instead of leaving every item as a ground box, and it can optionally scatter a boss’s drops around its corpse for a free-for-all. You turn it on and choose which items get vacuumed up and who is allowed to.

It ships as a native server module driven by Modules\LootManager\AutoLoot.ini, plus an easier companion Autoloot.lua in the same folder that lets you drive the whole thing from plain item codes. When the Lua’s Enable = true, it overrides both sections of the .ini.

PartWhere it livesIts job
Classic config.Server\Zoneserver\RF_Bin\Modules\LootManager\AutoLoot.ini[MagnetLoot] = which item tables are auto-picked and who qualifies; [MassiveLootBoss] = the boss corpse scatter.
Easy override…\Modules\LootManager\Autoloot.luaThe same feature by exact item codes, plus a “carry this key item” gate and a loot-everything switch. When its Enable = true it wins over the .ini.
Client halfNone — server-only. Players just see their inventory fill up; there is no client file or client toggle.
Off by defaultBoth files ship disabled (Enable = 0 in the .ini, Enable = false in the Lua), so nothing is auto-looted until you turn one on. Whichever file is in charge writes a plain-language line into the Module Logs AutoLoot.log telling you what it resolved.

How to activate it

  1. Choose the easy route (recommended) — the Lua. Open .Server\Zoneserver\RF_Bin\Modules\LootManager\Autoloot.lua and set the master switch on: 
    Autoloot = {
  Enable = true,
  TypeAutoLoot = 0,        -- 0 = all players
  LootAll = true,          -- pick up every drop (Items is then ignored)
  RequireItemCode = "",    -- or an item code a player must carry to auto-loot
}
    Save it — a running server re-reads it a moment later, no restart.
  2. … or the classic .ini. To drive it from AutoLoot.ini instead, leave the Lua Enable = false and set [MagnetLoot] Enable = 1, choosing the item tables to magnet and who qualifies (see the config below).
  3. (Optional) Scatter boss drops. Either add the nested MassiveLootBoss = { Enable = true, FreeForAll = false, Range = 40 } block in the Lua, or set [MassiveLootBoss] Enable = 1 in the .ini. Boss drops then burst out around the corpse instead of going straight to the owner.
  4. Test it. Kill a mob with a qualifying character — matching drops disappear off the floor and land in the inventory; kill a boss to see the scatter.
Do not delete the .iniAutoLoot.ini is required when the Zone server starts — deleting it stops the server from booting. To turn the feature off, set Enable = 0 (or the Lua Enable = false) instead.

The config files

Auto Loot has two files in Modules\LootManager\. The Lua, when enabled, owns the whole feature; otherwise the .ini rules.

AutoLoot.ini — two sections:

KeySectionMeaning
Enable[MagnetLoot]1 = auto-pick normal drops into the loot owner’s inventory, 0 = off.
TypeAutoLoot[MagnetLoot]Who may use the magnet: 0 all players, 1 only players carrying effect EffectCode, 2 billing type not 8, 3 VIP (degree != 0).
EffectCode[MagnetLoot]The item effect checked when TypeAutoLoot = 1.
TabListCnt + TabLXL0..[MagnetLoot]Which item tables are auto-picked (the stackables are 13,17,18,20,22,23,26,30,31,32,34,35).
BlackListCnt + BlackTable0 / BlackIndex0..[MagnetLoot]Table-code + index pairs that always drop as normal ground boxes.
Enable[MassiveLootBoss]1 = scatter boss drops around the corpse.
LA[MassiveLootBoss]1 = free-for-all (no loot owner), 0 = keep the killer’s loot rights.
RangeLoot[MassiveLootBoss]Scatter radius in world units (e.g. 40).

The Autoloot.lua override

If you would rather list exact item codes than table numbers, set the Lua’s Enable = true. It replaces both .ini sections — unless you delete the MassiveLootBoss block, in which case the .ini’s boss scatter stays in charge and only the magnet part follows the Lua.

FieldMeaning
Enabletrue = this file takes over (both .ini sections go quiet); false / omitted = the .ini rules.
TypeAutoLootSame 0 / 1 / 2 / 3 gate as the .ini.
EffectCodeUsed only when TypeAutoLoot = 1.
RequireItemCodeOptional key item. An exact item code a player must be carrying to auto-loot at all. "" = no carry gate. Checked on top of TypeAutoLoot.
LootAlltrue = pick up every drop (then only BlackList is respected and Items is ignored); false / omitted = only the Items codes.
ItemsThe whitelist of exact item codes (lower-case, copied from the item table) that get auto-picked. Only used when LootAll is false.
BlackListOptional exact codes that are never auto-picked.
MassiveLootBossNested { Enable, FreeForAll, Range } for the boss scatter (= the .ini’s LA / RangeLoot). Delete the whole block to leave boss scatter to the .ini.
The intended “key item” setupA common want is “only players holding a special ticket auto-loot everything.” That is RequireItemCode = the ticket’s item code together with LootAll = true — carrying it magnets every drop; everyone else loots normally.

Rules & limits

  • Codes, not table numbers, in the Lua. Items / BlackList / RequireItemCode use the exact lower-case item code (e.g. "irjad04"). A code that does not resolve is named in AutoLoot.log and simply never auto-loots — and a bad RequireItemCode disables the carry gate rather than locking everyone out.
  • The Lua wins wholesale. When Autoloot.lua parses with Enable = true, [MagnetLoot] and [MassiveLootBoss] in the .ini are both ignored — they do not merge, it is all-or-nothing.
  • Gates stack. TypeAutoLoot and RequireItemCode are checked together: a player must pass the type and, if you set one, be carrying the key item.
  • Empty whitelist = nothing. With LootAll = false and an empty Items, nothing is auto-picked — that combination is flagged in the log.

Off (both files disabled), Auto Loot is inert: every drop is a normal ground box and bosses drop normally.
