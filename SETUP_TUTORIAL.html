RF Online Server Setup Tutorial

Written for people with zero programming knowledge. If you can double-click and copy a folder, you can do this.

★What you are building

An RF Online private server is three programs working together, plus a database (the filing cabinet where accounts, characters and cash shop data are stored), plus the game client (the game itself on the player's PC).

ProgramFile you double-clickJob
Account ServerAccountServerSD.exeLogins, accounts, passwords
Login ServerLoginServerSD.exeServer list, billing / premium status
Zone (Game) ServerZoneServer_Regular_1_0_x64.exe (use run.bat)The game world: maps, monsters, characters

They must be started in that order, and all three talk to SQL Server databases named exactly:

RF_User      <- accounts and passwords
RF_World     <- characters, guilds, items, maps
Billing      <- cash shop and premium time

This tutorial walks you through: putting the files in the right places → creating those three databases → starting the servers → connecting the game.

✓Before you start — checklist

  • A PC running Windows 10 or Windows 11, 64-bit. Everything below happens on this PC (players can connect from other PCs later).
  • Microsoft SQL Server 2014 or newer installed. The free Express edition works fine. During its setup, choose Mixed Mode and remember the sa password you type.
  • Microsoft Command Line Utilities for SQL Server (the sqlcmd tool). Free download from Microsoft — search "Microsoft Command Line Utilities for SQL Server". Install it with Next → Next → Finish.
  • .NET Desktop Runtime 10 (x64) — free from Microsoft. Needed by the Account and Login servers.
  • Visual C++ 2015–2022 Redistributable, both the x64 and x86 versions — free from Microsoft. Needed by the Zone server and the game client.
  • The server folder you received (it contains the .AccountLogin, .Server and DB folders described below).
  • The license file ZoneServerSD.bin from your server owner. Without it the Zone server refuses to start.
  • An internet connection while starting the Zone server (the license is checked against online time).
  • About 30–45 minutes of quiet time.
Installing something above?Every installer listed is a normal Windows program: double-click the downloaded file, click Next until it finishes, click Finish. You never need to type commands for them.

1Know your folders

Your server folder looks like this. Do not rename or move anything — the programs find their settings by folder name.

YourServerFolder\ ├─ .AccountLogin\RF_Bin\ <- Account + Login servers live here │ ├─ AccountServerSD.exe double-click #1 │ ├─ LoginServerSD.exe double-click #2 │ ├─ AccountToolSD.exe makes player accounts │ ├─ (many .dll files) leave them alone │ ├─ Initialize\ its settings (AccountSystem.ini, LoginSystem.ini) │ ─ Settings\ legacy JSON - migrated into the .ini files once, then deleted (ignore it) ├─ DB\ database tools (this tutorial uses them) │ ├─ install_server_databases.bat <- creates RF_User / RF_World / Billing │ ├─ setup_odbc.bat <- connects Zone server to the databases │ ├─ schema\ the database blueprints (do not open) │ ─ setup_panel_databases.bat optional web-panel databases, skip for now ├─ .Server\Zoneserver\RF_Bin\ <- Zone (game) server lives here │ ├─ ZoneServer_Regular_1_0_x64.exe the game world program │ ├─ ZoneServerSD.bin YOUR LICENSE FILE - must stay in this folder │ ├─ run.bat double-click #3 (starts the Zone server) │ ├─ Initialize\ its settings (.ini files) │ ─ Modules\ game rules (.ini files) ├─ .Server\Zoneserver\WorldInfo\ server name + listen ports │ └─ WorldInfo.ini Notepad file (explained in step 4.3) └─ .Client\ the game client (give this folder to players)

In an assembled ready-to-run tree the same DB folder also appears as .AccountLogin\DB\ — identical contents, use whichever exists.

The license ruleZoneServerSD.bin must sit in the same folder as ZoneServer_Regular_1_0_x64.exe. If you move or delete it, the server shows a rejection popup and stops.

2Create the three databases

The databases RF_User, RF_World and Billing do not exist yet — you create them once with a ready-made script. No typing of database commands needed.

Option A — the installer script (recommended)

  1. Open the DB folder.
  2. Double-click install_server_databases.bat. A black window opens.
  3. It asks SQL Server name. If SQL Server is on this same PC, just press Enter. (Otherwise type the other PC's name.)
  4. It asks 1 or 2. Type 1 and Enter to use Windows Authentication (no password). Type 2 and Enter if you prefer the sa login, then type the sa password you chose when installing SQL Server.
  5. Wait. RF_World is large — a few minutes is normal. You will see one line per database: OK: RF_User created. etc.
  6. When it says Finished, press any key to close the window.
Safe to re-runIf a database already exists the script prints already exists - skipped and leaves your data untouched. A full report is always saved next to the script as install_server_databases_log.txt.
If it says "sqlcmd was not found"You skipped the "Command Line Utilities" item in the checklist. Install it, then run the script again.

Option B — the built-in wizard (if Option A is not available)

  1. Double-click AccountServerSD.exe, open its Setup menu.
  2. Page 1: choose SQL Server, point it at your SQL Server, press Install New DB → creates RF_User.
  3. Page 2: register your first world and install its database → creates RF_World. Keep the world database name exactly RF_World.
  4. Page 3: the Security Seed. Press the generate button and never change it again — accounts are locked to it.
  5. Then open LoginServerSD.exe → its Setup installs the Billing database.

3Connect the Zone server to the databases (ODBC)

The Zone server reaches the databases through "ODBC shortcuts" called DSNs. Think of a DSN as a saved bookmark: a name the server knows (“BILLING”, “RF_WORLD_AoP”) pointing at the real database (Billing, RF_World).

  1. Open the DB folder.
  2. Right-click setup_odbc.bat → Run as administrator → click Yes in the Windows popup.
  3. It prints the three bookmarks it created and says Done. Press any key.
Must be administratorA normal double-click is not enough for this one file — Windows only lets administrators create system DSNs.

4Check the settings files (Notepad only)

You will open a few files in Notepad: right-click the file → Open with → Notepad. Change only what is listed, then File → Save. Files 4.1 and 4.2 are the only ones you must check; 4.3–4.5 matter only when a server or the database lives on another PC.

4.1 .Server\Zoneserver\RF_Bin\Initialize\settings.ini

[System]
installed=1
autostart=1

[WorldDB]
trusted_connection=1
ID=sa
PWD=

[Billing]
IP=(local)
trusted_connection=1
DB=Billing
ID=sa
PWD=
  • trusted_connection=1 means "use Windows login, no password". Keep it 1 if SQL Server is on this PC and you installed it with your Windows account.
  • If you prefer the sa login instead: set trusted_connection=0 and fill ID=sa and PWD=yourSaPassword in both blocks. In the [Billing] block also keep IP=(local) (or the SQL Server PC's name) and DB=Billing.

4.2 .Server\Zoneserver\RF_Bin\Initialize\WorldSystem.ini

  • Find the line AccountAddress under [System].
  • If the Account server runs on this same PC: AccountAddress = 127.0.0.1.
  • If the Account server runs on another PC: type that PC's IP address, e.g. AccountAddress = 192.168.1.50.

4.3 .Server\Zoneserver\WorldInfo\WorldInfo.ini

  • WorldName under [System] is the name players see in their world list. Change it only if you want a different server name — it must never be empty or the Zone server refuses to start.
  • The port lines (AccountPort, GatePort, WebPort, BillingPort) are correct as shipped. Do not edit them unless you truly need to move a port: a wrong number stops the server at startup with a popup naming the bad line.
  • NationCode = PH picks the English item-name column. Leave it PH; it does not change billing or region.

4.4 .AccountLogin\RF_Bin\Initialize\AccountSystem.ini

[Database]
TrustedConnection=true
AccountDB_Machine=(local)
AccountDB_Name=RF_User

[World]
WorldSet_Num=1
Name0=RF ONLINE
DBName0=RF_World

[Listener]
LoginPort=27000
WorldPort=29000
ControlPort=28000
  • If SQL Server is on this PC with Windows login: keep TrustedConnection=true. For the sa login instead: set TrustedConnection=false and fill AccountDB_User / AccountDB_Password.
  • If SQL Server is on another PC: set AccountDB_Machine=thatPCname (and do the same in 4.5).
  • Argon2Salt under [System] is the password lock. Never change it once players exist, and keep it identical to the one in LoginSystem.ini (4.5).
  • The [Listener] ports (27000 / 29000 / 28000) are correct — leave them.

4.5 .AccountLogin\RF_Bin\Initialize\LoginSystem.ini

[Account]
AccountAddress=127.0.0.1
AccountPort=27000

[Network]
ClientPort=10001

[BILLING]
TrustedConnection=true
Database=Billing
  • AccountAddress is where the Account server lives: 127.0.0.1 when both run on this PC, otherwise that PC's IP. AccountPort must match 4.4's LoginPort (27000).
  • ClientPort=10001 is the port players connect to — leave it.
  • The billing database lines follow the same trusted/sa rule as 4.4.
  • Argon2Salt under [System] must be the same value as in AccountSystem.ini.

Everything else in these files (rates, events, nation = PH) is already pre-set for you. The Account/Login servers create the two .ini files above with correct defaults on first run — you only open them when the database or a server lives on another PC. Old Settings\appsettings.*.json files, if you ever see them, are a retired format: the servers copy them into the .ini once and delete them.

5The license file (why the server may refuse to start)

The Zone server only runs with a valid license file, ZoneServerSD.bin, sitting next to its .exe (see the red rule in step 1). When you press Start:

  1. The loading screen shows “License is loading.. 15 s” with a countdown — it is really checking the file against online Singapore time.
  2. Then “License is accepted.. 15 s” with a countdown.
  3. Only after both finish does the game world begin loading.

Two places show your license length, read straight from the file (for example a 1-year license shows 365 days):

  • The loading screen's top bar: ... | License: 365 days | ...
  • The main window's bottom-right corner: License: 365 days
If a popup appears insteadIt means the license was rejected: the file is missing, expired, edited, or the PC had no internet during the check. Fix = get a fresh ZoneServerSD.bin from your server owner, put it next to the .exe, make sure the internet works, try again.

6Start the servers (always in this order)

  1. Double-click .AccountLogin\RF_Bin\AccountServerSD.exe. A window opens; leave it open.
  2. Double-click .AccountLogin\RF_Bin\LoginServerSD.exe. Leave it open.
  3. Double-click .Server\Zoneserver\RF_Bin\run.bat. The Zone server window opens with a Start button.
  4. Click Start. Watch the loading screen: license loading 15 s → license accepted 15 s → the world loads. When the button disappears and the status bar at the bottom fills with numbers, the server is up.
Healthy signsBottom bar shows M: a number around 20000+, OPN: 1 - 1, and your license at the far right. The window title ends with [Started].
Stopping the serverUse the Server Close button in the Zone server window, then close the other two windows. Never just pull the plug on a running server — characters are saved on close.

7Create your first player account

  1. Double-click .AccountLogin\RF_Bin\AccountToolSD.exe.
  2. Use its register/create form: type a login ID and password, confirm, save.
  3. That account can now log in from the game client.

Make player accounts here (or in the Account server's own tools), not by editing the database by hand.

8Connect the game client

  • Playing on the server PC itself: open the .Client folder and double-click Launcher.exe, then press Play/Start in the launcher. It launches the game and connects to 127.0.0.1 automatically.
  • Playing from another PC: copy the whole .Client folder to that PC, install the x86 Visual C++ 2015–2022 Redistributable there, and set the server's IP inside the launcher settings file (System\XRFL\RFLSettings.bin is produced from RFLSettings.ini by RFLConfigConverter.exe — ask your server owner for the prepared client if you are not the owner).
  • Log in with the account from step 7, create a character, enter the world.
